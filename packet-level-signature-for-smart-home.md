# Extra Online Paper that I found
- [PINBALL: Universal and Robust Signature Extraction for Smart Home Devices](https://ieeexplore.ieee.org/abstract/document/9464026)
    - This paper presents **PINBALL**, claimed to be a tool that can automatically extract robust signatures for events happening on smart home devices.
    - It uses length distributions of bidirectional packets as signatures.
    - It is claimed to be more robust and achieve better detection accuracy than previous state-of-the-art methods. 
- [Signature-based and Behavior-based Attack Detection with Machine Learning for Home IoT Devices](https://ieeexplore.ieee.org/abstract/document/9293811)
    - This is more into protecting a home network based on signature and behavior.
    - Signature is generated by *Snort* software. 
- [Detecting Privacy Leakage of Smart Home Devices through Traffic Analysis](https://onlinelibrary.wiley.com/doi/full/10.1155/2022/5655314)
    - IoTEvent, a semiautomatic tool to detect vulnerable smart home devices, which is not limited to specific types of communication protocols
    - Handle UDP

### [Peek-a-Boo: I see your smart home activities, even encrypted!](https://arxiv.org/abs/1808.02741)
- **Priority**: <span style="background:#ff4d4f;color:white;padding:2px 8px;border-radius:4px;font-weight:600;">High Relevance</span>
- **Focus**: passive smart-home activity inference from encrypted/unencrypted WiFi, ZigBee, and BLE traffic.
- **ML Usage**: Multi-stage ML pipeline to identify device type, state, and user activity from passively sniffed traffic; reports >90% accuracy.

### [HomeSnitch: Behavior Transparency and Control for SmartHome IoT Devices](https://dl.acm.org/doi/epdf/10.1145/3317549.3323409)
- **Priority**: <span style="background:#ff4d4f;color:white;padding:2px 8px;border-radius:4px;font-weight:600;">High Relevance</span>
- **Focus**: Classifies semantic IoT behaviors from encrypted traffic without payload inspection.
- **ML Usage**: Supervised ML over connection-oriented application data-unit features; sources mention Random Forest, Gradient Boosting, and kNN, with encrypted behavior classification above 99% in the authors’ summary.

### [IoT Event Classification Based on Network Traffic](https://ieeexplore.ieee.org/document/9162885)
- **Priority**: <span style="background:#ff4d4f;color:white;padding:2px 8px;border-radius:4px;font-weight:600;">High Relevance</span>
- **Focus**: Very close to your paper scope: event/action classification from encrypted IoT traffic metadata.
- **ML Usage**: Uses packet metadata such as length and traffic rate; compares k-NN, Random Forest, SVM, and Majority Voting.

### [Classifying IoT Devices in Smart Environments Using Network Traffic Characteristics](https://ieeexplore.ieee.org/document/8440758)
- **Priority**: <span style="background:#faad14;color:black;padding:2px 8px;border-radius:4px;font-weight:600;">Medium Relevance</span>
- **Focus**: Device fingerprinting rather than event inference; useful background for “device type leakage.”
- **ML Usage**: Multi-stage classifiers using traffic attributes; reports very high IoT device identification accuracy.

### [Characterizing and classifying IoT traffic in smart cities and campuses](https://ieeexplore.ieee.org/document/81164381)
- **Priority**: <span style="background:#faad14;color:black;padding:2px 8px;border-radius:4px;font-weight:600;">Medium Relevance</span>
- **Focus**: Earlier UNSW smart-environment dataset/classification work; useful for baselines and datasets.
- **ML Usage**: Uses statistical traffic attributes to classify IoT vs non-IoT and identify devices with >95% accuracy.

### [Information Exposure From Consumer IoT Devices: A Multidimensional, Network-Informed Measurement Approach](https://dl.acm.org/doi/10.1145/3355369.3355577)
- **Priority**: <span style="background:#faad14;color:black;padding:2px 8px;border-radius:4px;font-weight:600;">Medium Relevance</span>
- **Focus**: Broader measurement paper; important dataset/source for privacy exposure.
- **ML Usage**: Not primarily an ML paper, but includes classifier-style inference of user/device behavior from encrypted or plaintext traffic.

### [HoMonit: Monitoring Smart Home Apps from Encrypted Traffic](https://dl.acm.org/doi/10.1145/3243734.3243820)
- **Priority**: <span style="background:#52c41a;color:white;padding:2px 8px;border-radius:4px;font-weight:600;">Low Relevance</span>
- **Focus**: Security-monitoring angle: encrypted traffic fingerprints reveal SmartApp behavior/misbehavior.
- **ML Usage**: More program-analysis + side-channel fingerprinting than ML-centric; still relevant as encrypted-traffic behavior inference.

### [ChatterHub: Privacy Invasion via Smart Home Hub](https://ieeexplore.ieee.org/document/9556231)
- **Priority**: <span style="background:#ff4d4f;color:white;padding:2px 8px;border-radius:4px;font-weight:600;">High Relevance</span>
- **Focus**: Segments encrypted hub traffic, extracts traffic patterns, and maps them to events such as lock, switch, motion, and LED state changes.
- **ML Usage**: Feeds segmented traces with event labels into ML classifiers to infer smart-home events and occupancy/activity routines. This is one of the closest follow-ups to PINGPONG/PINBALL.

### [TrafficSpy: Disaggregating VPN-encrypted IoT Network Traffic for User Privacy Inference](https://ieeexplore.ieee.org/document/9947251)
- **Priority**: <span style="background:#ff4d4f;color:white;padding:2px 8px;border-radius:4px;font-weight:600;">High Relevance</span>
- **Focus**: Uses whole-house VPN-encrypted traffic-rate traces and disaggregates them into individual IoT-device traffic signals.
- **ML Usage**: Uses a factorial hidden Markov model for disaggregation and evaluates ML/DL adaptive attacks on the recovered traces to infer sensitive user information. Particularly useful if your paper discusses VPNs as a defense.

### [Deep Fingerprinting: Undermining Website Fingerprinting Defenses with Deep Learning](https://arxiv.org/abs/1801.02265)
- **Priority**: <span style="background:#faad14;color:black;padding:2px 8px;border-radius:4px;font-weight:600;">Medium Relevance</span>
- **Focus**: Represents Tor traffic traces as packet-direction/sequence patterns and attacks website-fingerprinting defenses such as WTF-PAD and Walkie-Talkie.
- **ML Usage**: Uses a CNN architecture to learn fingerprints automatically; reports >98% accuracy on undefended Tor traffic and >90% against WTF-PAD.
